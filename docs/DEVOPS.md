# Development and release workflow
Owner approved automatic future publishing on 2026-11-01, after checks. Public URL stays https://fmq-6d9.pages.dev/ ; repository is renamed Luisa, retaining its ID/history. No new paid services or schedules.

## One bounded job
1. Read the short handoff/rules and relevant requirement IDs. Inspect git status, worktrees and open PRs. Never replace unfinished owner work.
2. Create an issue with a user goal, requirement IDs, acceptance checklist, tests/manual evidence, risk and dependencies. One branch and PR per job. Group tiny related documentation chores.
3. Implement on `task/<issue>-<slug>`; the lead owns shared CI/config/catalogues. Use targeted tests, one heavy job at a time. Delegation only when authorised; fresh brief and worktree, no forks.
4. Run `python3 scripts/luisa.py gate`. This checks register consistency, available catalogue resources, file sizes, tooling tests, basic secret patterns and static packaging. Source/maths/visual/interaction/print checks remain explicit for teaching changes.
5. Review the diff before opening PR. Use an independent reviewer for security, routing, shared rendering/print geometry or complex mathematics; self-review focused documentation chores. Record findings; fix instead of suppressing checks.
6. Push branch, open PR with acceptance table. Wait for `build`, `test`, `scan` on the exact head; missing or failed required checks prevent landing. Squash merge through `scripts/land.py` when authenticated GitHub CLI is available, or the equivalent reviewed GitHub UI flow. No force pushes or direct production edits.
7. Cloudflare builds the merged commit using `python3 scripts/luisa.py gate` with output directory `dist` once dashboard configuration is confirmed. GitHub main protections must require build/test/scan. Until both are verified, report the enforcement gap; never claim gates are enforced just because files exist.
8. Verify build-manifest revision/version and actual changed slides/JSON/PDF destinations online; reject HTML fallback bodies. A pipeline start is not successful publication. Record release evidence, update handoff and send the mandatory final owner email under standing authorisation FR-024, unless the owner explicitly defers that particular report. Follow docs/handoff/RELEASE-EMAIL.md; preserve and report any pending notification.

## Build, run and rollback
`python3 scripts/luisa.py build` creates the owner profile in `dist/`; `python3 scripts/luisa.py build --profile student` creates the ADA student profile in `dist-student/`. The owner profile preserves the Cloudflare v0.39 features and access arrangements. The student profile removes offline packs, online textbook chapter PDFs, CG100 and links to the owner's edition, while retaining the approved teaching, practice, print and solutions routes. These host differences are owner-approved under ED-040 and are checked against separate `edition` values in each build manifest. CI builds and checks both profiles; do not compare the two manifests as if the hosts must match.

The static artifact is not an authentication boundary. Do not publish the student artifact to a static directory until ADA routes all HTML and private assets through an authenticated server runtime, with durable account state/backups outside the public tree and fail-closed behavior. A client-side password form or hidden links do not protect PDFs, JSON, images or question-bearing JavaScript. After deployment is enabled, verify ADA against the `student` manifest and Cloudflare against the `owner` manifest. Verify each live host independently against its intended profile.

The public artifact excludes docs, .git, materials, usage and credentials. Unmarked directories cannot be erased by the build. Serve a local artifact with `python3 scripts/luisa.py serve --directory dist --port 8778`; loopback only. This static preview does not verify authentication. Keep commit SHA and artifact digest with each release. Roll back Cloudflare to its known successful owner deployment; roll back ADA to a checked student artifact while preserving the separate private authentication database and backups. Never reset/overwrite working main. Verify the rollback online against the matching host profile.

The local master remains _LUISA/website; materials/ and backups/ stay alongside. Private WORKSPACE.json in LUISA_STATE_DIR maps machine paths, mail sender and authoring roots. New machine: clone repo, install Python reference, gate/build/serve; supply private source materials only for chapter-authoring tasks. Full historical slide-generation environment is not yet portable.

## ADA student deployment prerequisite
The current ADA access is SSH upload to a public static directory. That capability alone cannot serve a protected student edition. Before deployment, the ADA manager must provide a supported server-side runtime/reverse-proxy route for every student path, private durable storage and backups outside the public tree, a manager-controlled deploy/restart path, and the relevant HTTPS/cache/logging configuration. Credentials, host, target and browser URL live in private WORKSPACE.json; never place them in public docs.

The repository now includes a Flask WSGI gateway in `student_server/`, with Argon2 password hashes, one-use temporary credentials, database-backed revocable sessions, admin TOTP MFA and guarded static delivery. This code remains private application source; `scripts/luisa.py build --profile student` only creates the student content artifact. Install `requirements-auth.txt` into the manager's Python 3.12 virtual environment and run `student_server.wsgi:application` under a supervised Gunicorn process bound to loopback. Configure `LUISA_STUDENT_BUILD_DIR`, `LUISA_STUDENT_DATABASE`, `LUISA_ADMIN_PASSWORD_HASH`, `LUISA_ADMIN_TOTP_SECRET`, `LUISA_SCHOOL_YEAR`, `LUISA_URL_PREFIX` and `LUISA_COOKIE_PATH` through the manager's protected environment facility. For ADA use `/AL` for both prefix and cookie path. Keep the database and secrets outside every public/static directory. `scripts/bootstrap_student_admin.py` prompts for a teacher password, writes a new mode-0600 environment file and provisions a TOTP seed; run it only over the manager's private host session and enroll the seed in the teacher authenticator immediately. Do not run it in CI or a terminal whose output is retained.

The HTTPS reverse proxy must redirect HTTP to HTTPS and route the complete `/AL/` prefix, including PDF, JSON, image, CSS, JavaScript and `sw.js` requests, to the WSGI gateway. It must overwrite `X-Forwarded-Proto` with its trusted scheme value; the WSGI app trusts one proxy hop for that header and rejects non-HTTPS application requests. Remove static-file fallback for that prefix: when the app is down, return an error rather than serving files. The gateway sets private no-store headers on all responses, idle/absolute session expiry and short-lived in-memory rate-limit counters keyed by a one-way identifier digest; it does not retain student IPs or login history. Run one Gunicorn worker unless a shared rate-limit mechanism is configured. Nginx currently has access logging enabled, so the manager must provide its exact logged fields/retention plus upstream/CDN policies before rollout; do not assume application logging controls infrastructure logs.

Initialize the private SQLite schema with `flask --app student_server.app:create_app init-db`. Keep SQLite state and its backups outside the artifact path. The app exposes `backup_database(source, destination, public_root)` for consistent snapshots; recovery must restore a copy in private storage, then verify the admin page and accounts before activation. Manager-controlled secrets/MFA bootstrap, HTTPS redirect, proxy route, service supervision, file permissions and backup schedule remain deployment work and require manager access.

Use document-relative asset/navigation URLs and explicit .html page destinations. Never assume deployment at /. Catalogue JSON/PDF links must also stay within the deployment prefix. Test with a plain static server under a non-root prefix before release. Check the student migration against a previously provisioned browser and report any cached downloads that remain on a device. The owner edition retains its existing SW/offline behavior; the student profile disables registration and packs and includes only a one-time cache migration worker. Do not deploy the student profile as a public static site.

Stage the student artifact outside public, verify every manifest hash, then activate it only behind the authenticated route. Do not copy source books, development docs, Git metadata or usage/credentials into public. Verify ADA's student manifest and protected resource routes; separately verify Cloudflare still reports the owner manifest and owner experience. Report an ADA failure as an incomplete student rollout even if Cloudflare succeeds. Student authentication state and backups must survive website deployments and rollbacks.

## ADA retention (owner instruction 2026-11-03)
Keep only the latest verified Luisa release on ADA. Do not retain historical Luisa releases, source/deployment ZIPs or completed staging folders there. Recovery artifacts remain outside ADA (Cloudflare and the local OneDrive backup). Check disk capacity before staging; reuse identical files from the current deployment where possible. Verify the staged artifact and activate by directory switch rather than duplicating the complete release. After live verification, remove superseded Luisa directories and temporary staging artifacts, preserving unrelated server files.

PDF reader modules use .js filenames because ADA serves .mjs as application/octet-stream. Verify the live module Content-Type as well as its hash; local browser testing alone cannot establish host MIME compatibility.
