# Authoritative requirements
`register.json` is the sole editable product and development requirement register. `REQUIREMENTS.md` is generated by `python3 scripts/luisa.py requirements`.
Read only the IDs relevant to the current issue; the short mandatory standard is in root AGENTS.md.

Historical implementation assertions are preserved, not promoted to current verification. The imported 91-row register and specific feedback predate later releases; current status must be reconciled against exact artifact checksums and evidence. A previous green render does not prove mathematical/source or print acceptance.

Use implementation: not_assessed / planned / in_progress / historical_record / implemented / superseded. Use verification: not_checked / needs_revalidation / partially_checked / verified / not_applicable. `verified` requires nonempty evidence. Do not compute a misleading global completion percentage from mixed scopes.

Evidence records identify input/output hashes, reviewer, date, checks, viewport/page sizes and source comparison. Keep private corrections and screenshots outside the public repository; reference their private evidence ID without private paths. Shared renderer changes invalidate dependent approvals.

Precedence: white backgrounds supersede old blue/yellow title pages; numbered pale-blue covers and unobstructed answers supersede ?/tick instructions; Luisa supersedes MARS/FMQ; .01 increments supersede version 2; no hourly schedules remain authorised. Future-work requests go to deferred scope unless explicitly activated.

Source reconciliation: all 91 legacy IDs and every recorded Pure 2 Chapter 1 feedback ID were imported. Later instructions from the owner conversation are identified by FR-/OPS-/DEV-/FB- IDs. Originals, maintenance records, past PDFs and image evidence are retained privately under the master materials folder. This is a reconciled requirement register, not a claim of a fresh full-library acceptance audit.
