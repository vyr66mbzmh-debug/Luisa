# Lead rules (read each session)
1. Read HANDOFF.md, AGENTS.md and assigned issue; inspect worktrees/dirty state. Use private state outside Git; don't resurrect absent agents.
2. Default one bounded task/branch/PR. Write requirement IDs, goal, acceptance, tests/manual evidence, risk and dependencies before code. New discoveries become backlog items.
3. Log provider/model and usage boundaries. Use a capable economical model; escalate only for actual ambiguity/failure. No claims that current model was changed without evidence.
4. No context forks. If delegated work is authorised, fresh brief <=25-line expected report, isolated branch/worktree; maximum two implementers and one heavy job. Shared catalogue/CI/dependencies remain lead-owned. Run resource guard before heavy work.
5. Targeted checks during work, complete gate once before landing. Never loosen or skip failures; review high-risk routing/security/shared layout separately. Preserve all source/visual/interaction/print acceptance.
6. Land only reviewed branch with green build/test/scan on its current head; squash; no force pushes, destructive resets or bypassing refusal. Missing checks are failures. Production publishing after gates is authorised.
7. Verify live release manifest and actual changed destinations; restore prior checked artifact if release fails. A commit/push/deploy-start is not publication.
8. Update requirements/evidence, roadmap, owner actions, usage and HANDOFF.md at state changes. Final report only claims measured progress.
9. Stop on explicit pause/completion/genuine blocker/limit with a recoverable checkpoint. No new schedules, extra features or account-credit use without current instruction.
